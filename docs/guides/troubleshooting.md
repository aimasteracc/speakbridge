# 故障排查

[返回文档索引](../README.md)

先确认应用版本、失败的功能和完整错误类别。分享问题时保留版本与错误码即可，不贴 API Key、真实会议正文或包含个人路径的日志。历史报告中的一次服务错误不能证明现在仍有同样问题。

## API、翻译与纪要

| 现象 | 检查与处理 |
| --- | --- |
| “所选 API 引擎需要密钥” | 在声桥设置中保存密钥，确认“已加密保存”；平台上发出了 Key 并不等于应用已配置。Soniox 与通用 Key 分开保存 |
| DeepSeek 能用于文字，录音却连接失败 | 把语音转写明确设为本地，翻译与纪要设为 API。自动模式见到通用 Key 会优先选 API 语音；DeepSeek 文字接口不能代替 Realtime 语音接口 |
| 404、协议不支持或模型不存在 | 核对 API 地址和模型名。程序追加 `/responses`，不要重复拼接；仅 Chat Completions 兼容并不足够 |
| 401 / 403、CLI 登录错误 | 核对密钥权限，或用对应官方 CLI 重新登录。不要把登录令牌发到对话框或写入项目文件 |
| 余额不足 / Quota | 在对应服务检查额度。Harness / CLI 不会绕过模型服务的额度要求 |
| 500 / 503 / 429 | 查看有限重试的结果，再稍后重试；旧纪要会保留。不能只凭这些错误认定会议太长 |
| 等待超时或输出截断 | 检查选中模型及[容量、输出预算、超时](meeting-notes.md#长会议与模型容量)；不是一味增加字数上限。网络断流后不能把部分文本当作成功纪要 |
| 中文会议输出成日文，或反之 | 在纪要生成时手动指定语言。混合语言或短文本可能误判；该选择与翻译目标和界面语言独立 |
| 连接测试通过，但某次纪要失败 | 测试仅证明固定短请求当时可用，不证明长会议、输出预算或后续服务始终正常。查看该记录保存的具体错误 |

## 听写没有进入输入框

按顺序检查：

1. 在“语音输入”检查所选模式是否就绪、模型是否下载，以及麦克风和输入权限。
2. Mac 授权后重新检查；新版或移动过路径的应用可能与旧授权条目不同。若系统要求 Touch ID／密码，由用户在系统窗口完成。
3. 点击目标应用的普通文字输入框，用“测试自动输入（不录音）”验证输入链路。
4. 如果键盘没有右 Option，关闭按住模式，使用 `Cmd/Ctrl + Shift + D`；如果快捷键被占用，在快捷键页更改。
5. 录音期间不要切换窗口、输入框或光标；密码框、自绘控件、只读控件以及 Windows 更高权限窗口可能不支持。
6. 检查是否开启了文字整理。整理失败会保留原文并停止自动输入，不等于识别没有结果。
7. 仅在明确零写入时使用补填；可能已经写入时先检查正文，避免重复整段输入。

详细流程和恢复边界见[跨应用听写](dictation.md)。不要通过关闭密码框保护、强行重试或提权注入来绕过失败。

## 录音、本地模型与识别

| 现象 | 检查与处理 |
| --- | --- |
| 麦克风无音量 | 检查系统麦克风权限、输入设备与音量；Windows 允许桌面应用访问 |
| 只录到麦克风，没录到电脑声音 | 确认音频来源、系统音频授权与共享音频选择；开发模式优先改用打包应用检查 |
| 说话被重复识别 | 混合采集时扬声器声音可能再次进入麦克风，使用耳机并检查声源 |
| 模型未就绪或下载校验失败 | 核对选中的模型，完成下载与校验后再开始；应用不会自动换成收费引擎 |
| 初稿反复修改、停顿后才定稿 | 本地识别按音频窗口修订预览；增强识别还需复核。流式视觉效果不能消除模型推理和断句等待 |
| 纯“。”不断出现 | 当前新转写过滤完整的纯标点假设；旧历史的此类行只隐藏，不改写底层旧记录。先确认实际运行版本 |
| 使用更大模型仍有错字 | 检查音频清晰度、源语言、术语与模型限制。词典只是提示；模型与文字整理都不能保证零错误 |

## 构建失败

`Windows helper is missing or stale` 即使在 Mac 上也可能出现：构建入口会先检查 Windows 组件，生成二进制不在 Git 中。请按[原生构建依赖](../development.md#原生构建依赖)准备 .NET SDK 与 net48 参考程序集，再配置两个环境变量。不要把未验证的旧二进制塞入仓库跳过哈希检查。

其他依赖问题先使用项目锁文件执行 `npm ci`，并核对 Node 与目标系统架构。没有远程 CI 或实机成功证据时，应保留“待验证”，不根据本地旧产物宣称新机器可运行。
