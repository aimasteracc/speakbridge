# 0.7.10：多语言、模型容量与纪要失败处理

## 已确认的问题

- 0.7.9 固定使用日文提示词，中文会议也会输出日文。
- 原有 100,000 字符限制不反映模型上下文容量。用户指定的长记录有 473 段、约 40,016 字符，未触及旧限制，不能把这条记录失败归因于该字数上限。
- 旧版只设置 8,192 输出 token、180 秒超时，没有流式进度或持久错误信息。DeepSeek 默认启用思考，推理 token 也计入输出预算；这是旧流程的限制，但不是已证明的历史失败原因。
- 2026-11-03 的新版本实测中，指定长记录收到 HTTP 503 / `service_unavailable_error`。固定公开短文本在 Responses API 的普通、流式、默认思考及低思考模式也收到 503；Chat Completions 普通请求收到 503，流式请求建立连接后 45 秒未完成。没有将这些失败写成成功验收。

## 最终行为

- 按转写原文的字符语言特征识别中文、日文、英文，用户可手动覆盖。生成语言与界面语言、翻译目标分开。混合语言或极短文本可能需要手动选择。
- 三种模板保持七部分结构，区分明确决定与待讨论事项，缺失信息标为不明/待定。保留材料来源与完整性说明，资料内的命令按引用内容处理。
- 输入不按统一字符数截断。容量已知且输入估算容纳得下时完整发送原文；超出模型预算时逐段整理再汇总，保留尾段，不跳过失败片段，不静默截断。
- 未知模型由服务端判定容量，可在设置中指定部署容量、输出预算及超时。分段总结有压缩信息的固有限制；容量足够时不会启用。
- token 计数使用明确标注的规划估算，不冒充 tokenizer。包括提示词和 JSON 包装，预留 5% 上下文余量以及输出空间；服务端最终判定为准。
- DeepSeek 纪要关闭思考模式，默认单次请求 600 秒；自动输出预算 32,768 token。模型允许且上下文仍有余量时，输出截断会提高预算重试一次。手动输出预算不会擅自增加。
- API 流式进度只显示可见文本字数，不显示或保存推理过程；必须收到完成事件才保存。503/500/429 最多自动重试两次，等待 2 秒、5 秒并参考 `Retry-After`（最多等待 60 秒）。身份、余额、网络断流错误不自动重复提交。
- 可以取消，迟到结果不能覆盖旧纪要或恢复已删除记录。失败消息保存到本地记录，重新打开可见；关闭详情不中止任务。
- 明确选择 API 引擎时，关闭翻译也会实际测试固定文字请求，避免仅测试本地识别就误报 API 通过。
