# 0.5.2 连续出字与纯句号问题

最近一段用户本地 SenseVoice 会话有 171 个片段，其中 33 个仅为“。”。本轮只读取片段类型统计用于诊断，没有复制用户语音或正文，也没有改写用户历史。代码原来仅检查文本是否非空，导致这种结果被显示、保存并送去翻译。

## 修复范围

对本地、OpenAI 兼容接口和 Soniox 的**完整转写假设**过滤纯标点 / 空白；不逐 token 删除标点。这样，“你好”之后单独返回的“。”仍可组成“你好。”，但无正文的独立句号段会被丢弃。有意单独口述、且被识别器转换成标点的片段也会被此规则省略。撤回已有初稿时从当前会话中移除对应行并持久化；识别错误提示保留。

本地无效识别不再先插入空的“正在识别”行，避免在噪声中不断闪出占位行。旧历史的纯标点行在显示层隐藏，磁盘与旧导出数据保持原样。

上一版只让整批新字淡入。此版让增长部分按 Unicode 字素逐步显示，每字约 28 ms，整批最多 360 ms 补齐。SenseVoice 几乎每次都把句末临时句号改成新内容，不能只把 `startsWith` 的变化当作追加：已显示的位置立即采用最新内容，后续增长部分继续展开。句中修改且尾部词语不变时整体纠正，避免把旧尾部重新打出来。最终结果、历史文本、减少动态效果和后台窗口不排队显示。

## 验证与解释

- 50 个单元测试通过，包含纯标点、正常句尾、小数、日期、多语言短答、独立流式标点 token、撤回、Unicode 与有界显示。
- 10 项 Electron 视觉场景验证同一输入批次确实产生多个不同的可见字符串，并覆盖连续修订、停止补齐、历史纯标点隐藏与逐字换行时的阅读锚点。
- `tests/local-cleanup.e2e.cjs` 先通过本地解码 fixture 重现“。→定稿”“有初稿→被撤回”，再运行真实 SenseVoice 与 VAD。新历史只保留正常句子，纯标点保存数量为 0。
- 使用既有公开中文录音按原速送入，实际识别更新 17 次、显示更新 86 次（开发运行）/ 88 次（最终 Mac arm64 包）；最终文字与 0.5.0 同一录音的 SenseVoice 输出完全一致。它说明显示更细密，并不表示模型解码快了 5 倍或识别率提高。首次可见文字约 1847 ms；结果仅限这段本机录音。精确交付包结果在 `test-artifacts/local-cleanup-0.5.2.json`。
- 原有 8 项桌面功能和 Soniox 本机 WebSocket fixture 验证新无效行不会进入历史；没有调用付费云服务。演示视频采用预设文字，仅展示显示策略。

本轮没有修改音频切分、VAD 阈值、模型、词典或预览频率。没有录制用户麦克风，没有原版同条件录像，不声称“零误识别”或已完全复现原版。SenseVoice 仍为按窗口重复解码；此处的逐字呈现属于显示层，Soniox 才是当前已接入的原生云端流式选项。
